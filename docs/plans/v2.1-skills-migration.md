# AgentShell v2.0 → v2.1: Skills-Based Architecture Migration

**Date:** 2025-12-27
**Type:** Architecture Migration
**Impact:** Breaking Change
**Scope:** Global (.context repository, affects all projects)

---

## Problem

Subprocess-based agents cause user confusion:
1. User runs `/aang:plan`
2. Subprocess spawns, does work, returns
3. User: "Who am I talking to?" "What was that for?"
4. Context is lost

---

## Solution

Convert agents to skills (run in current conversation):
1. User runs `/aang:plan`
2. Claude transforms into Aang
3. Aang: "I'm Aang, strategic planner..."
4. Continuous conversation, no confusion

---

## Migration Tasks

### Task 1: Folder Structure
```bash
mkdir -p ~/.context/skills/{agents,workflows}
mkdir -p ~/.claude/skills/{agents,workflows}
mv ~/.context/agents ~/.context/agents.v2.0-archived
mv ~/.claude/agents ~/.claude/agents.v2.0-archived
```

### Task 2: Convert Agents
- `agents/aang-planner.md` → `skills/agents/aang:plan.md`
- `agents/aang-task-writer.md` → `skills/agents/aang:task.md`
- `agents/m-o-executor.md` → `skills/agents/mo:turbo.md`
- `agents/m-o-executor-eco.md` → `skills/agents/mo:eco.md`

### Task 3: Move Workflows
```bash
mv ~/.context/skills/{commit,pr}.md ~/.context/skills/workflows/
```

### Task 4: Update Commands
Update command descriptions to reference skills not subagents.

### Task 5: Add Folder Routing
Agents suggest:
- Plans → `docs/plans/{phase}/`
- Tasks → `docs/tasks/{phase}/`
